# city-salary · 城市工资计算器（Agent Skill）

一个开箱即用的**按城市计算工资**的 Agent Skill：社保、公积金、个人所得税、年终奖、历史明细与趋势图，打开先选城市，按当地政策实时计算。**已内置广东 21 市 + 北京 / 上海**（23 城），可扩展全国地市。

同时兼容多种 Agent 工具（Claude Code / Codex / opencode / TRAE / WorkBuddy 等），既可作为 **Agent Skills（SKILL.md）** 安装，也可作为项目指令（**AGENTS.md**）使用。

## 功能

- **城市选择**：打开计算器强制选择城市，各市参数独立，切换即生效
  - 广东 21 市：深圳/广州/东莞/佛山/珠海/惠州/江门/中山/汕头/韶关/湛江/肇庆/茂名/梅州/汕尾/河源/阳江/清远/潮州/揭阳/云浮
  - 直辖市：北京、上海（2026 年度参数，五险统一基数、公积金比例上限 7%、北京医保个人含 3 元大额医疗互助）
- **单月计算**：税前工资 → 五险（养老/医疗/失业/生育/工伤，基数各自独立可调）→ 公积金（0 或 5%~当地上限）→ 个税（累计预扣预缴）→ 到手现金；支持七项专项附加扣除（勾选启用、强制上限、互斥二选一）、税优健康险/个人养老金/企业年金年度抵扣
- **年终奖**：单独计税 + 六个临界值陷阱速查（36000/144000/300000/420000/660000/960000），命中自动警告
- **历史明细**：逐月可调工资与基数，按累计预扣计算每月个税；当前月后自动生成预测月份（虚线显示）；累计汇总 + 可筛选系列的趋势图（SVG 折线、双侧坐标轴、悬停高亮）；一键导出 PDF
- **数据时效**：内置核查机制，**每年 1 月核查医保费率、7 月核查养老/公积金基数**（不同险种调整周期不同，分双检查点）

## 口径说明（影响"到手多少钱"的三条关键约定）

1. **大病医疗只在年度汇算清缴时扣除**，不进月度预扣预缴——模板中该项只影响年度预估，不影响当月税额
2. **补充扣除既减税也从实发中扣现金**：个人养老金、企业年金个人缴费、税优健康险都是个人真实支出，工资条中列为扣款项，最后一行是"到手现金"而非"实发工资"
3. **企业年金个人缴费**按"本人缴费工资计税基数"计算（模板以养老缴费基数作为该基数），不是按税前月薪的 4%

## 仓库结构

```
city-salary/
├── SKILL.md                 # skill 的镜像副本（便于在 GitHub 直接阅读）
├── AGENTS.md                # 通用 Agent 项目指令（Codex/opencode/TRAE 等读取）
├── skills/
│   └── city-salary/
│       ├── SKILL.md         # ★ 源文件：Anthropic Agent Skills 标准格式
│       └── assets/
│           └── calculator.html  # ★ 源文件：完整交互式计算器（单文件 HTML，零依赖）
├── site/
│   └── index.html           # 计算器镜像副本（用于 GitHub Pages 等静态托管）
├── tools/                   # 零依赖 Node 脚本：测试与维护
│   ├── test-calc.js         #   530 项断言：税率表/年终奖陷阱/端到端算例/D1D2 回归
│   ├── check-dom.js         #   静态结构检查：重复 id、悬空引用、未定义处理器
│   ├── check-sync.js        #   漂移检查：镜像是否同步、城市参数是否都写进了文档
│   ├── test-export.js       #   导出 PDF 的降级链测试
│   └── sync.js              #   把 skills/ 下的源文件同步到镜像位置
└── docs/                    # 各工具安装文档
```

**注意**：`skills/city-salary/` 下的两份文件才是源文件；根级 `SKILL.md` 与 `site/index.html` 是镜像副本。改完请执行 `node tools/sync.js`，并用 `node tools/check-sync.js` 确认没有漂移。

## 维护与测试

```bash
node tools/test-calc.js     # 计算回归（改参数/改逻辑后必跑）
node tools/check-dom.js     # 单文件 HTML 的静态结构检查
node tools/check-sync.js    # 镜像与文档漂移检查
node tools/test-export.js   # 导出 PDF 降级链
node tools/sync.js          # 同步源文件到镜像位置
```

全部为零依赖 Node 脚本，无需 `npm install`，可直接作为 CI 门禁。测试的做法是**从 `calculator.html` 里抽取真实的 `<script>` 放到最小 DOM 桩上执行**——测的是真正会跑在用户浏览器里的那份代码，而不是测试文件里重写一遍的副本。

## 使用示例

对话中直接说：

- “我月薪 7500，深圳，社保公积金基数 6750，公积金 5%，非独生赡养老人，到手多少？”
- “月薪 3 万在北京，公积金按 12% 缴，到手多少？”
- “上海月薪 2 万，公积金 7%，还要扣个人养老金 1000，实际到手现金多少？”
- “年终奖 15 万要交多少税？”
- “打开工资计算器，选广州”

Agent 会自动提取参数、追问缺失项、按所选城市政策计算并主动提示优化空间（公积金比例提升、年终奖陷阱、未用扣除项等）。

## 扩展全国地市

在 `skills/city-salary/assets/calculator.html` 的 `CITIES` 对象中新增一行，并在 `SKILL.md` / `AGENTS.md` 参数表补一行（`node tools/check-sync.js` 会检查有没有漏）。两种城市形态各有工厂函数：

```js
// 广东型：五险基数各自独立
CITIES.城市key = CI("城市名",
  {min:医保下限, max:医保上限, comp:单位费率, emp:个人费率},
  生育参数(null 表示并入医保), {min:公积金下限, max:公积金上限},
  养老下限(默认4775), {note:"数据说明"});

// 直辖市型：五险共用一个基数区间
CITIES.城市key = CIU("城市名",
  {min:统一基数下限, max:统一基数上限},
  {medComp:医保单位费率, medEmp:医保个人费率, unempComp:失业单位, unempEmp:失业个人,
   injComp:工伤费率, hfRateMax:公积金比例上限, medFixEmp:医保个人每月固定额},
  {min:公积金下限, max:公积金上限}, {note:"数据说明"});
```

⚠️ **别把外省城市套进 `CI()`**：它的养老上限 27549、失业/工伤区间 2520~44265 都是广东省级标准，套到外省会算错。

## 数据说明

- **广东**：2025-2026 年度，最近核查 2026-08-12（结论：2026 年 7 月广东基数未调整）
- **北京**：2026 年度，五险基数 7,270~36,348（京人社发〔2026〕7号，2026.7 起）；公积金基数 2,540~36,348、比例 5%-12%（京房公积金管委会办〔2026〕6号）；医保含生育单位 9.8%、个人 2%+3 元大额医疗互助
- **上海**：2026 年度，五险基数 7,546~37,731（市人社局 2026-08-18 公示，2026.7.1 起）；公积金基数 2,740~37,731、单位与个人各 5%-7%（市住房公积金管委会 2026-08-18 通知）；医保含生育单位 9%（阶段性降费，有效期至 2027-02-28）、个人 2%；失业 0.5%+0.5%、工伤一类 0.2% 起（沪人社规〔2024〕25号）；长护险从医保统筹基金划转、不扣个人
- **核查节奏**：医保/生育按自然年（1 月）调整，养老/失业/工伤/公积金按社保年度（7 月）调整——两套周期，需分别核查
- 湛江/肇庆/河源医保单位费率为第三方参考值，揭阳为官方文件（揭医保〔2025〕67号 / 揭府规〔2022〕6号），模板内均已标注
