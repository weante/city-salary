# 城市工资计算器（按城市选择当地政策）

## 触发条件

用户提及以下任一关键词时激活：工资、薪资计算、到手工资、社保计算、公积金计算、个税计算、年终奖计税、五险一金、税后收入、工资条、实发工资（并涉及具体城市时）。

已内置城市：深圳/广州/东莞/佛山/珠海/惠州/江门/中山/汕头/韶关/湛江/肇庆/茂名/梅州/汕尾/河源/阳江/清远/潮州/揭阳/云浮（广东21市，可继续扩展全国地市）。

## 数据时效检查（每次运行第一步，强制执行）

各地社保/公积金基数每年 7 月调整，**7 月 15 日**为年度切换判定点。每次运行本 Skill，先按以下三步判断数据是否过期：

1. **看系统时间**：Bash 执行 `date "+%Y-%m-%d"` 获取当前日期。
2. **看数据时间**：查看下方"数据状态"里的**最近核查日期**（即 skill 内社保公积金数据最后一次联网获取/核对的时间）。
3. **判断是否联网**：
   - 若 `当前日期 >= 当年7月15日` **且** `最近核查日期 < 当年7月15日`（即 7 月 15 日之后还在用去年的数据，当年未核查过）→ **必须联网搜索**最新基数（养老/医疗/失业/生育/工伤/公积金上下限及比例），对比更新
   - 否则（当年已核查过，或还没到当年 7 月 15 日）→ 直接使用现有参数，无需联网

联网搜索后的处理：
- 官方基数有变化 → 更新下方参数表、assets/calculator.html 中 CITIES 常量、模板页脚数据依据，并告知用户最新生效数字
- 官方确认未调整 → 更新"最近核查日期"，沿用现有参数
- 网络不可用 → 明确告知用户数据可能过期，用现有参数计算但标注"数据未经最新核查"

### 数据状态

- 数据年度：2025-2026年度（养老/失业基数 2025.7-2026.6 执行；医疗/生育 2026.1-12 执行；公积金 2026 年度）
- **最近核查日期：2026-08-12**（结论：2026年7月广东基数未调整，参数有效）
- 下次需联网的触发条件：当前日期 ≥ 2027-07-15（届时最近核查日期仍为 2026-08-12，属于"去年数据"，自动触发搜索）

## 渲染交互式计算器

当用户需要可视化计算器时，使用 widget_path 模式渲染：

```
qoder_show_widget({
  title: "city_salary_calculator",
  widget_path: "city-salary/assets/calculator.html"
})
```

计算器模板位于本 Skill 的 `assets/calculator.html`，包含全部输入控件和实时计算逻辑。**打开页面强制选择城市**，各市参数独立。模板包含两个页面：

- **单月计算**：全部参数输入与明细、年终奖陷阱、工资条
- **历史明细**：从就业月起逐月可独立调整工资/五险基数/公积金基数/比例，按累计预扣预缴计算每月个税；当前月之后自动生成**预测月份行**（蓝色标记，可取消勾选，图表中预测段用虚线），含累计汇总、可筛选系列的趋势图（SVG 折线、双侧坐标轴、**悬停高亮**：放大数据点、加粗曲线、虚线定位到坐标轴并显示数值）、导出 PDF（html2canvas+jsPDF，CDN 加载失败自动回退 window.print）

## 城市参数结构（扩展全国地市的方法）

模板中每个城市用 `CI()` 工厂函数定义（见 assets/calculator.html），新增城市只需添加一行：

```js
CITIES.城市key = CI("城市名",
  {min:医保基数下限, max:医保基数上限, comp:医保单位费率, emp:医保个人费率},
  生育参数(可null, 默认并入医保单位费率),
  {min:公积金基数下限, max:公积金基数上限},
  养老基数下限(默认4775),
  可选标记 {hukou:true, tier2:true, ltc:true, med2:{...}, note:"数据说明"}
);
```

城市 flag 说明：`hukou`（户籍切换，仅深圳有）、`tier2`（医疗二档，仅深圳有）、`ltc`（长护险开关，深圳 0.125%、珠海/东莞/清远 0.15%）、`note`（政策说明文字，显示在页脚）、`warn`（数据待确认标记，显示为橙框）。

数据状态说明：**茂名**公积金基数为 2025 年度（2026 年度通知已发布但未见具体数字，橙框"数据待确认"）；**汕尾**单建统筹总费率 4.8% 官方已确认（待遇清单 2026 年版），但未拆分个人比例，按个人 0 计；其余城市均为官方文件数据。揭阳数据来源：基数（揭医保〔2025〕67号，2026年度 3727~18636）、费率（揭府规〔2022〕6号，单位6%/个人2%）。

### 长期护理险（第六险）现状

- **已实施**：广州（2016年试点，个人约0.12%从医保个账代扣、35岁以下在职免缴，不影响到手现金）；梅州（2025.7起，合计0.5%从医保费划转，不额外负担）

### 住房公积金

缴存比例**只能是 0 或 5%~12%**（0 表示未缴存；1-4 为非法值自动归 0；个人=单位）。默认 5%。比例 0 时公积金基数自动置 0，恢复时还原。

### 医疗档次限制

- **深圳**：一档/二档可选；**深户强制一档**
- **东莞**：三档可选——统账结合(有个账) 单位5%/个人2%、统账结合(无个账) 单位4.5%/个人0.5%、单建统筹 单位2.45%/个人0.5%；另缴生育险0.7%（单位）
- **珠海**：一档(统账)6%/1.5%、二档(单建)3%/0%
- **佛山/惠州/中山/汕头/湛江/汕尾**：统账结合 vs 单建统筹两档（单建个人多为0）
- **潮州**：综合医保(其他单位/财政拨款) vs 住院医保(单建)三档

### 专项附加扣除（七项，互斥规则，有上限）

每项需勾选启用，不勾选则为 0；勾选自动填入默认值（子女教育/婴幼儿照护 2000、赡养老人 1500、住房租金按城市标准），填写范围 0~税务局规定上限：

- **子女教育** 2000元/子女/月（上限10000，勾选默认2000）⟷ **3岁以下婴幼儿照护** 2000元/子女/月（上限10000，勾选默认2000）—— 同一子女二选一
- **住房贷款利息** 1000元/月（上限1000）⟷ **住房租金** 按工作城市档位 —— 二选一，不可同时享受
- **继续教育** 400元/月（学历，上限48个月）或 3600元/年（职业资格）
- **赡养老人** 独生子女3000元/月，非独生分摊≤1500元/人（上限3000，勾选默认1500）
- **大病医疗** 年度自付超15000部分，限额80000元/年（汇算清缴时扣，月均≤6667）

**住房租金扣除标准（按税务局三档规定，依据工作城市市辖区户籍人口判定）**：
- **1500元/月**：广州、深圳（省会/计划单列市）
- **1100元/月**：佛山、东莞、中山、珠海、惠州、汕头、湛江、茂名、揭阳、清远、江门、肇庆、潮州、梅州、阳江、韶关（市辖区户籍人口超100万）
- **800元/月**：汕尾、河源、云浮（市辖区户籍人口≤100万）

### 补充扣除（年度）

- **税优健康险** ≤200元/月（2400元/年）
- **个人养老金** ≤1000元/月（12000元/年）
- **企业年金(个人)** ≤本人缴费工资计税基数的4%

## 计算步骤

1. **确定基数**：五险基数各自独立设置（按所选城市的上下限），默认均为该市最低基数；超出上下限自动夹取。
2. **个人社保** = 养老8% + 医疗(个人费率) + 失业0.2% + 长护0.125%(仅深圳可选)
3. **个人公积金** = 公积金基数 × 缴存比例(0 或 5%~12%，默认5%)
4. **月扣除合计** = 个人社保 + 个人公积金 + 5000(免征额) + 专项附加扣除(仅勾选启用项)
5. **累计预扣预缴**：已就业月数 = 当前月份 − 本年度开始就业月份 + 1；累计应纳税所得额 = 月薪×已就业月数 − 月扣除×已就业月数 → 查税率表 → 累计税额 − 上月累计税额 = 当月个税
6. **实发工资** = 税前月薪 − 个人社保 − 个人公积金 − 当月个税
7. **年度预估**：按本年度就业月数（12 − 就业起始月 + 1）计算，加入税优健康险+个人养老金+企业年金扣除后重新计算年度税额
8. **年终奖**：奖金÷12找月均税率 → 奖金×税率-速算扣除数 → 检查临界值陷阱

默认值：各险种基数均为所选城市最低基数、公积金比例5%、当前月份自动读取本地时间、本年度就业起始月默认1月。

## 自然语言交互流程

### 第一步：确认城市 + 提取已知信息 + 追问缺失参数

用户给出工资查询时，**首先确认城市**（已内置的 21 市之一；未提及时用 AskUserQuestion 让用户选择；用户报出未内置城市时，告知可联网补充该市数据），再提取已知信息并追问：

**必须确认**（直接影响结果）：
- 工作城市（未给出时询问）
- 税前月薪（如未给出）
- 医疗档次：仅深圳询问一档/二档；其他市单档
- 户籍：仅深圳询问深户/非深户

**应当追问**（可能显著影响到手工资）：
- 社保/公积金缴费基数是否等于月薪（很多公司按最低基数缴）
- 公积金缴存比例（5%和12%差距很大）
- 是否有专项附加扣除（子女教育、房贷/房租、赡养老人等）
- 是否有年终奖

**可选追问**（进一步优化）：
- 税优健康险、个人养老金、企业年金
- 当前是几月（累计预扣预缴，年初和年末税额不同）

### 第二步：计算并展示

用清晰的明细格式展示：税前工资 → 各项社保扣除 → 公积金扣除 → 应纳税所得额 → 个税 → 实发工资。

如果用户需要交互式计算器，渲染本 Skill 的 `assets/calculator.html` 模板。

### 第三步：主动提示

计算完成后，主动提示以下可能影响实际到手的内容：
- 如果公积金比例较低，提示"若公积金比例从X%提到12%，每月多存Y元（免税）"
- 如果年终奖处于临界值陷阱区间，**必须警告**并给出建议金额
- 如果有未使用的专项附加扣除，提示可节税金额
- 如果社保基数低于实际工资，提示这影响养老金和医保账户
- 如果月薪较高（>35000），提示个人养老金和税优健康险的节税效果

## Pitfalls

- 各险种基数上下限不同，不能用同一个 clamp 范围
- 深户/非深户差异仅在单位养老比例(17% vs 16%)，个人部分相同(8%)
- 住房贷款利息和住房租金不可同时享受，必须二选一
- 子女教育和婴幼儿照护针对同一子女不可同时享受
- 年终奖临界值陷阱：36000/144000/300000/420000/660000/960000 这六个点，多1元可能少拿数千至数万元
- 累计预扣预缴意味着同一工资在1月和12月的个税可能不同（税率跳档）
- 长护险目前仍在征求意见阶段，默认不计入，需用户确认
- 大病医疗只能在年度汇算清缴时扣除，不能月度预扣
- 企业年金个人缴费扣除上限为本人缴费工资计税基数的4%，不是月薪的4%
- 社保基数和公积金基数可以不同，且很多公司不按实际工资缴纳
- 切换城市后各险种基数自动重置为该市最低值，需提醒用户重新确认

## Verification

- 用 node 脚本验证关键计算节点：社保各项金额、累计预扣税额、年终奖陷阱差值
- 对照当地人社局/医保局官网公布的缴费标准核实基数上下限
- 年终奖六个临界值的"多1元少拿"金额必须精确验证
- 每年7月15日后需检查基数是否更新（各地市独立核查）
