## 二、阻塞情况（如实记录）

**核查在 2026-09-30 因搜索服务全面限流而暂停。** 逐项诊断结果：

| 路径 | 状态 | 说明 |
|------|------|------|
| Brave Search（curl） | **429** | 或返回降级页（74KB 但**不含查询词**） |
| Jina Reader | **000** | 连不上 |
| DDG Lite | 202 | 返回页面但无结果链接 |
| Bing（本地 Chrome） | 失败 | DOM 仅 435 字符，页面未加载 |
| 360 搜索（本地 Chrome） | 可用但**命中不了政府源** | 4 个查询均 0 条 `.gov.cn` |
| Yandex / Ecosia | 反爬挑战 | "Are you not a robot?" |
| 搜狗 | 仅图片/新闻 | |
| DSH 原生 `web_search` | 不可用 | 无 API key |
| DSH 原生 `web_fetch` | 不可用 | 沙箱拒绝（non-public IP） |
| agent-reach Exa | 未安装 | `mcporter` 缺失 |

**根因**：6 个核查子代理并发猛打 Brave 与 Jina，触发 IP 级限流；且它们持续请求使限流窗口无法滑过。已全部停止。

**为什么"限流"必须与"查不到"分开**：限流返回的空结果若被写成「未找到」，就是**假结论**——比没核查更糟，因为它看起来像已核查过。`research.js` 现在会返回 `[RATE-LIMITED]` / `[FETCH-FAILED]` 标记，报告中必须单列。

## 三、本轮修掉的过程缺陷（比核查本身更耐用）

| # | 缺陷 | 后果 | 修复 |
|:-:|------|------|------|
| 1 | 政策文档**只记文号、不记 URL** | 7 份 `policy-*.md` 实测**零个链接** → 重新核查无法回到源头，只能从零搜索；而搜索恰是最易被限流的一环 | SOP 第 3 步改为必须记 URL（`79fa4e0`） |
| 2 | 6 个子代理并发无节制 | 打到限流，反而拖慢整体进度并污染结论 | SOP 明确并发 ≤2~3、间隔 ≥10s（`efa634d`） |
| 3 | 工具把限流当"没结果" | 会产出假的「未找到」 | 退避重试 + `RATE-LIMITED` 标记（`83157ad`） |
| 4 | Jina 带浏览器 UA 被反爬 | 返回挑战页被当正文，抽取全空却不报错 | 搜索/抓页分用两套 UA（`d787016`） |
| 5 | 只按长度判断抓取成功 | 5.8KB 挑战页被当正文 | 加 `BLOCK_PAGE` 识别 |

## 五、下一步

1. **等限流窗口滑过**（停止并发请求后通常数十分钟至数小时），先复测 Brave 与 Jina。
2. 恢复后**并发压到 2~3 个**、每请求间隔 ≥10 秒，按省分组推进。
3. 若搜索仍不可用，改走**直接导航已知政府站点**（不依赖搜索引擎）：
   先取各省人社厅/医保局/公积金中心的「通知公告」栏目页，再逐条抓取。
4. 每个批次完成后：更新 `CITIES` → 五件套文档 → `gen-warn-backlog.js --update` → 全量 `npm test` → 提交推送。
5. 本轮新增的 URL 记录要求，从**下一次**调研开始执行；现有 7 份文档的 URL 缺口
   在下次核查对应省份时顺带补上。
