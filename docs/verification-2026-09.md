## 〇、为什么暂停（一句话）

**能抓页，但找不到页。** 抓取（Jina / 本地 Chrome）时好时坏但基本可用；
**搜索**——也就是"从零发现某个市的官方通知在哪"——已穷尽 15 条路径，全部不可用。
没有搜索就无法系统性地发现政府来源，337 城核查无法推进。

### 已穷尽的搜索路径（全部实测）

| # | 路径 | 结果 |
|:-:|------|------|
| 1 | DSH 原生 `web_search` | 不可用：无 API key |
| 2 | DSH 原生 `web_fetch` | 不可用：沙箱拒绝（hostname resolves to a non-public IP） |
| 3 | agent-reach Exa 搜索 | 不可用：`mcporter` 未安装 |
| 4 | Brave Search（curl） | **429** / 000 / 降级页（74KB 但不含查询词） |

| 7 | Bing（本地 Chrome） | 页面加载失败（DOM 仅 435 字符） |
| 8 | **360 搜索（本地 Chrome）** | **可用**，但 4 个查询均 **0 条 `.gov.cn`**（结果多为 360 自家页与社保资讯站） |
| 9 | 搜狗（Chrome / Jina） | 返回多为图片与新闻 |
| 10 | Yandex | 反爬挑战（"Are you not a robot?"） |
| 11 | Ecosia | 反爬挑战 |

| 13 | Mojeek | 000 |

| 15 | 直接导航政府站点 | 江西人社厅 `hrss.jiangxi.gov.cn` Jina 与 Chrome 均抓不到 |

**网络本身正常**：`example.com` / `api.github.com` / `www.so.com` 均 200。

### 解除阻塞的可行途径（按成本排序）

1. **配置搜索 API key**（最彻底）：DSH 原生 `web_search` 报错提示需要 `DEEPSEEK_API_KEY`
   （凭据服务或启动环境变量均可）。配好后 `web_search` 直接可用，不再依赖爬取。
2. **等待限流窗口滑过**：本轮限流由 6 个子代理并发触发，停止后 Jina 曾恢复 200。
   Brave 的 429 可能需更长时间。恢复后**必须把并发压到 2~3 个、间隔 ≥10 秒**。
3. **换网络出口**：当前出口 IP 已被多家搜索服务标记。
4. **人工提供一批政府 URL**：只要给出各省人社厅/医保局/公积金中心的「通知公告」栏目页，
   抓取环节（Jina / Chrome）就能接力完成，无需搜索。

## 二、本轮修掉的过程缺陷（比核查本身更耐用）

| # | 缺陷 | 后果 | 修复 |
|:-:|------|------|------|
| 1 | 政策文档**只记文号、不记 URL** | 7 份 `policy-*.md` 实测**零个链接** → 重新核查无法回到源头，只能从零搜索；而搜索恰是最易被限流的一环 | SOP 第 3 步改为必须记 URL（`79fa4e0`） |
| 2 | 6 个子代理并发无节制 | 打到限流，反而拖慢整体进度并污染结论 | SOP 明确并发 ≤2~3、间隔 ≥10s（`efa634d`） |
| 3 | 工具把限流当"没结果" | 会产出**假的「未找到」结论**——比没核查更糟 | 退避重试 + `RATE-LIMITED` 标记（`83157ad`） |
| 4 | Jina 带浏览器 UA 被反爬 | 返回挑战页被当正文，抽取全空却不报错 | 搜索/抓页分用两套 UA（`d787016`） |
| 5 | 只按长度判断抓取成功 | 5.8KB 挑战页被当正文 | 加 `BLOCK_PAGE` 识别 |
| 6 | 抓页只有一条路 | 南京公积金 Jina 返 0 而 Chrome 能拿全文；江苏税务反之 | Jina 失败自动兜底 Chrome |

## 四、解除阻塞后的推进计划

1. **先复测** Brave 与 Jina；恢复后并发压到 2~3 个、每请求间隔 ≥10 秒。
2. 按省分组推进，每组完成后：更新 `CITIES` → 五件套文档 →
   `node tools/gen-warn-backlog.js --update` → 全量 `npm test` → 提交推送。
3. **优先补 172 个 warn 城市**（缺口已知，核查价值最高）。
4. 调研时**同时记录来源 URL**（本轮新增的 SOP 要求）；现有 7 份文档的 URL 缺口
   在核查对应省份时顺带补上。
