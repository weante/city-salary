### `web_search` 401 的根因（已定位）

**`DEEPSEEK_API_KEY` 槽位里放的是 OpenCode Zen 的密钥，不是 DeepSeek 平台密钥。**

诊断证据（全程未打印密钥值）：

| 项 | 观察 |
|----|------|
| 前缀/长度 | `oc_sk_…`，51 字符（**DeepSeek 平台密钥是 `sk-` 开头**） |
| `OPENCODE_GO_API_KEY` | 同样 `oc_sk_…`、51 字符（两者不同，但同格式） |
| 报错指纹 | `****X8DF` ↔ 存储值后缀 `…xIX8DF`，**确认就是它被发出去了** |
| 发往 `api.deepseek.com/anthropic/v1/messages` | **401** invalid |
| 发往 `opencode.ai/zen/go/v1/…` | **400 MissingSessionID** → **认证通过** |
| 发往 `opencode.ai/zen/v1/messages` | **402 Insufficient account funds** → 认证通过，**账户余额不足** |

**结论**：该 key 对 OpenCode 网关有效、对 DeepSeek 平台无效。
`web_search` 走的是 `api.deepseek.com`，故 401。

**修复方式**：在**侧栏 → 插件 → 官方 → 网页搜索**里填入**真正的 DeepSeek 平台密钥**
（`platform.deepseek.com` 签发，`sk-` 开头）。填 OpenCode 的 key 无效。

> **时间线**：本会话早前 `web_search` 正常（完成了江苏/云南/海南等多项核查），
> 凭据文件 `~/.dsh/.credentials.yaml` 于 **2026-09-30 20:41 被重建**，此后即 401。
> 即**此前可用的密钥被替换成了 OpenCode 的密钥**。

**操作约束（血的教训）**：并发核查任务 ≤2~3 个，抓页请求间隔 ≥10 秒。
上次 6 个并发直接把 Brave 打到 429、Jina 打到连不上，反而拖慢进度。

**必须区分的两种"没查到"**：
- `[FETCH-FAILED]` / `[RATE-LIMITED]` → **因抓取失败未能核查**（不代表数据不存在）
- 确实打开了官方页面、页面上确实没有该数据 → **已确认未找到**

两者混用会产出**假结论**——比没核查更糟，因为它看起来像已核查过。

## 一之十、README 的数值从来没人核对 —— 黑龙江错了 12 轮

这轮换了个方法：**先把守卫链的覆盖面列出来，再探测没被覆盖的地方**，而不是一份份文档碰运气。

**探测方式**：故意破坏三处，看有没有守卫反应。

| 破坏点 | 结果 |
|--------|------|
| README 里的西藏基数 `7,172.4~35,862` → `9,999.9~99,999` | **无人管** |

#### ⚠️ 本批最重要的教训：全口径 ≠ 城镇非私营

省统计局 [《2025年河南省城镇单位就业人员工资平稳增长》解读](http://tjj.henan.gov.cn/2026/07-27/3379784.html)（省统计局人口和就业统计处处长胡昶昶）公布「2025 年全省**城镇非私营单位**就业人员年平均工资 **91023 元**（+5.6%）、城镇私营单位 52941 元」。

`91023 ÷ 12 = 7585.25 ≠ 6520`。社保缴费基数用的是**全口径**（`6520 × 12 = 78240 元/年`），与统计局的城镇非私营口径**不是同一口径、不可互推**，且统计解读稿**从不公布全口径数**：

- ❌ 不可用 `91023 ÷ 12 × 3 = 22755.75` 填社保上限（会高约 16%）；
- ❌ 也不可用 6520 反推统计口径数据；
- ✅ 只能直接引用人社件的 6520 / 3912 / 19560。

#### 方法论（可复用）

1. **省级「统一基数」文件往往同时覆盖五险**，查人社厅时别只找养老。
2. **四部门联合发文是最强的一手件**（人社+医保+财政+税务），一次钉死社保与医保两个口径。
3. **「暂按上年核定 + 待差额结算」是过渡状态**，正式件到手必须替换，不能长期当默认值。
4. **省人社厅真实域名常不带 `www`**（`www.hrss.henan.gov.cn` NXDOMAIN，`hrss.henan.gov.cn` 才在）。
5. **年度基数通知挂在「履职依据」栏目**，且列表栏可能是 JS 空壳；首页锚点里的最新文件才是突破口。
6. **列表页 grep 关键词常得 0 命中** —— 标题是《关于公布…上下限标准的通知》，必须逐条打开文章。
7. **解 `warn` 必须逐城复核理由**，不能因为「同省同件」就一并解除。

|:-:|------|------|
| 1 | [浙人社发〔2025〕52号原文](https://rlsbt.zj.gov.cn/art/2025/9/18/art_1229506773_2569490.html)（`rlsbt.zj.gov.cn`，发文 2025-09-17，有效性「有效」） | 「2025 年下限按 **2023 年**加权平均工资（**8310 元/月**）的 60% 确定」→ 8310×0.6 = **4986**、8432.83×3 = **25299** |
| 2 | [浙江税务官方 Q&A](https://zhejiang.chinatax.gov.cn/art/2025/12/11/art_13314_645797.html) | 明确「**从 2025 年 1 月 1 日起**」→ **浙江基数是自然年度，不是 7 月-次年 6 月**，直接否掉聚合站的「2026.7.1–2027.6.30」 |
| 3 | 省人社厅「行政规范性文件 > 社会保障类」栏目（[列表页](https://rlsbt.zj.gov.cn/col/col1229506773/index.html)） | **最新一条是 2025-12-16，整个栏目没有任何 2026 年文件**；「政策解读」与规范性文件总表最新均止于 2026-09-14 |
| 4 | [诸暨市人力社保局](https://www.zhuji.gov.cn/col/col1229074495/art/2026/art_a6870176fbd44e92b79ed28870a63672.html)（发布 2026-05-11） | 「目前缴费基数下限为 **4986** 元，上限为 **25299** 元」 |

**决定性的一点：聚合站自己的算术是错的。** 66zhonglv 称 4986 是「社平 8433 的 60%」，
但 **8433 × 0.6 = 5059.8 ≠ 4986**；真实关系是 **4986 = 8310 × 0.6**。
且该站自家两张表互相矛盾（19548 说「2026.7.1–2027.6.30」，19602 说「下半年 7-12 月」）。
另：「浙人社发〔2025〕65号」这个文号**查不到任何官方对应文件**，
按浙江编号规律 2026 年基数通知应为「浙人社发〔2026〕xx号」。

**结论**：仓库 `4986~25299` + `dataYear="2025"` + 11 市 `warn` **全部保持不变**。

**残留不确定性（如实记录）**：2025 年那版是 **2025-09-17** 发的，今天 **2026-09-30**，
理论上正值发布窗口期。多次抓取省厅各栏目，最新条目止于 2026-09-14，未发现基数文件——
**但不能 100% 排除"最近两周刚发布而未被抓到"**。已要求子代理补一次定向核查。

**方法论教训（比结论更重要）**：
1. **二手来源可能有硬性算术错误**，且同一站点的不同页面会互相矛盾——不能只数"几个来源"。
2. **"多个独立来源"不等于"可信"**：台州新闻与 66zhonglv 很可能同源（都抄同一篇通稿）。
3. **判断省份基数是否更新，先确认该省的社保年度口径**（自然年 vs 7月-次年6月）——
   我最初就是被"7 月已过"这个错误前提带偏的。
4. **假警报也有价值**：它暴露了"该省社保年度口径"这一此前未记录的属性，
   已补入本报告。且**没有在拿到官方源之前改数据**，这个纪律守住了。

### 本轮的方法论教训：我自己重新引入了守卫要防的那类 bug

排查"哪些省的五险基数在 SKILL.md 里缺失"时，我用正则 `(?<![\d.])22607(?![\d])` 判断，
**得出「福建/贵州/内蒙古 3 省缺失」的结论，还给 SKILL.md 加了 3 段说明**。

**结论是错的。** 那 3 省的养老基数**本来就在 SKILL.md 里**（第 324/407/432 行），
只是写成 **`4,043 ~ 22,607`（带千分位逗号）**，我的正则不认逗号。

**最讽刺的一点**：守卫里的 `numbersIn()` 正是为这类问题写的——它的注释明写着
「文档写 5901.40 而代码是 5901.4，子串匹配会漏；反过来更长数字里的子串
（如 2330 命中 12330）也不会再被误判为命中」。**我在扩展这个守卫时，恰恰重新引入了它要防的 bug。**

**教训**：
1. **判断"某值是否出现在文档里"必须复用 `numbersIn`，不要自己写正则** —— 千分位逗号、
   小数位数、长数字子串这三类陷阱，`numbersIn` 都已处理。
2. **守卫报"通过"时，先怀疑自己的实验工具**。我当时第一反应是"守卫失效了"，
   实际是守卫正确、我的分析脚本错误——做了 5 轮调试才定位。
3. 冗余的说明已撤销（避免与原有内容重复）；守卫保留（它本身是有效的）。

### 五、8 条方法论

1. **.docx 用 PowerShell 解 zip 读 `word/document.xml`**：正文常在附件里，页面只有「点击下载」。
2. **⚠️ 提取条目别按花括号深度截断** —— `{min:…,max:…}` 在第一行就闭合；正解是从 `CIU("名"` 行向后找第一个匹配 `/\}\),?\s*$/` 的行。
3. **⚠️ JS 字符串拼接漏加号的报错行号指向文件末尾**，二分查找会被误导（`[,''])[1].replace(` 应为 `[,''])[1]+'').replace(`）。
4. **在 CRLF 文件里插入多行块注释必须用 `join('\r\n')` 或事后 `replace(/[^\r]\n/g,'\r\n')`**，否则留下裸 LF（本批 4 处）。
5. **断言的属性路径是 `.med.comp` / `.med.emp`**，不是 `.medComp` / `.medEmp`（后者会 13 条全红）。且批量替换若以目标断言串**起点**为区间终点，会漏掉最后一行。
6. **⚠️ 电子税务局「税费知识库」不是官方件**：`id=489895`/`490978`/`W230922001816063` 这类问答库条目可以当线索，不能当依据；一旦拿到市级规范性文件必须改值并留修正痕迹。
7. **⚠️ 阶段性降费件与现行件要分开记**：北海三件 2016/2021/2022 降费件执行期均已过，只能记「not-found 现行费率」，不能拿来当现值。
8. **⚠️ 政府门户页面里有「政务通」伪附件 URL**：形如 `http://rsj--nanning--gov--cn-3c31cb6a11.zip`，是把域名编码进扩展名的占位，不是真附件。

#### 五、本批方法论（11 条）

1. ⭐⭐ **政府门户检索 API 的 `url` 字段可反查市级事业单位真实域名**（汉中公积金中心 `zfgjj.hanzhong.gov.cn` 即由此找到，DoH 猜 10 个名字全错）。前提是**省略 `catalogId` 参数**才是全站搜索；响应 `data.records[].url` 直接给出部门子站完整 URL。
2. ⭐⭐ **二进制下载必须用 `curl -o` 直写磁盘**，任何 `execFileSync(..., {encoding:'utf8'})` 都会把 PDF/PNG/JPG 的非法字节静默转成 U+FFFD。诊断信号：PIL `UnidentifiedImageError`、pypdf `incorrect startxref`、**WinRT 渲染出全白页且各页字节数完全相同**。
3. ⭐⭐ **降费/减征政策件往往比费率办法更容易拿到分解值**：衡水 2020 年减征通知里「由 7% 调至 3.5%」「生育 0.8%」直接把 7.8% 拆出来，与办法第十一条的 9.8% 交叉互证，且有四组数字同时自洽（企业 9.8%、机关 9.3%、灵活就业 9%）。
4. ⭐ **跨件算式互证比单件自校验更实用**：找出「单位合计费率条款」与「拆分费率条款」，两者相减即得单位费率。
5. ⭐⭐ **SPA 政府站点破解三步**：首页 anchor → 功能页 `<script src>` → 读功能页专属 JS 抄出 channelId 与 JSON 端点（邯郸公积金 `channelIds:232` + `350179.json?id=`，20 分钟攻克）。
6. ⭐ **TRS 系站点栏目层级**：`xxgk_gknb_list.shtml`（法定主动公开，含 `gfwj` 规范性文件）→ `common_list.shtml` → `secondLevelChannel.shtml`（二级栏）。**分页规律：`createPageHTML(…,栏目名,'shtml',总条数)` → 第 1 页用裸栏目名，第 N≥2 页用 `栏目名_N.shtml`，`_1.shtml` 反而 404**。
7. ⭐ **市公积金中心年度缴存基数通知不一定在「政策法规/中心文件」栏** —— 汉中在「新闻中心›通知公告」、渭南在「住房公积金›政策法规」、安挂在 CMS 首页，三栏都要翻。
8. ⭐ **政府门户检索 API 两种通用形态**：① 表单 GET 型 `…/jrobot/search.do?webid=1&q=<关键词>`，结果 href 是 `/jrobot/plugin/link/show.do?url=<编码后的真实URL>` 包装；② 带反爬头的 JSON 型，需 `tjmabc` + `md5(tjmabc)` 双头。
9. ⚠ **CMS 第 1 页空壳 ≠ 栏目无内容，必须翻分页**；**`index.shtml` 永久空白不代表栏目为空**（模板调 `htmlData()` 而该函数在所有外部 js 里都未定义，`index_2.shtml` 起却正常）。承德的 `/col/colXXXX/index.html` 是全通用栏目加载节点，条目由 `sessionStorage['area']` 驱动的 JS 异步加载，静态抓取永远为空。
10. ⚠ **扫描件定位条款的省法**：先 OCR 前 5 页（基金筹集通常在第二、三章），再 OCR 末 2 页查有效期与废止条款，中间页 OCR 返回空属正常。OCR 噪声靠算式自校验剔除。
11. ⚠ **部门域名缩写不可跨省套用**（湖北 `rst.`/`rsj.`、孝感 `sylbzj.`；河南 `hrss.`/`zzrs.`/`pyrs.`）；猜一个不通**不能**断定「该省不可达」。

#### 八、方法论（本批新增）

1. ⭐ **「现行有效规范性文件目录」一页证伪法**：政府门户普遍有把所有现行有效规范性文件连文号列成一张表的目录页，一次 GET 即可判断某文号是否存在且仍有效。**法理边界：只收录政府/政府办公厅文件、不含局发文件**，故只能用于证伪巴政办发〔2020〕11号、通政发〔2022〕85号这类市政府级文号，不能用于判断包医保发〔2022〕11号、锡医保发〔2021〕111号、阿医保办〔2019〕115号等局发件。
2. ⭐ **用「灵活就业生育费率」反推「企业单位生育费率」**：内医保办发〔2025〕22号 强制二者相等，故任一市公布的灵活就业生育费率在法律上即该市企业单位生育费率。这是本区目前唯一有效的数值取值线索，值得横向复制到其余 6 市盟的「政策解读/访谈」栏。
3. ⭐ **403 与 headless Chrome 软 404 都可能只是路径少写 `index.html`**（锡林郭勒亲证：不带 403/软 404，带 index.html 得 200/44601）。判 dead-end 前必须试 index.html 变体。
4. 内蒙古**没有**安徽那种动态 `.js` 友情链接文件，页脚是服务端静态 HTML 且**只给 7 个盟市**（缺通辽/巴彦淖尔/兴安盟/乌兰察布），同时混列 18 个外省省局域名，抓取须过滤。jrobot 检索 API 在三市盟全废（bynr 301 / xam 404 / huhhot 000）。
5. `web_search` 本轮两次 HTTP 429（OpenCode Zen 额度耗尽），全部成果来自直接 curl 官方站点枚举 —— **搜索引擎不可用时，门户枚举仍是主路径**。
6. ⚠ **记录库字段坑：`confirms` 不能为空**。`tools/source-records.js:37` 的 `STUB_RE = /尚未核查|占位|待核查|待查|待补充|^$|^无$|^-$/` 含 `^$`，**空 confirms 的条目会被 `isFilled` 判为未填而整体跳过**（`mismatch` 仍会被统计，所以会出现「mismatchCount 涨了但 best 没切换、urls 没涨」的怪现象）。新建记录必须写实质 `confirms`。
7. ⚠ **记录库 URL 去重**：批量清理用脚本（按 city 逐条 `Set` 去重 + 尾部空参数归一），不要手改。
