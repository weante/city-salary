# 计算口径白皮书（calculation-spec）

> 这份文档回答一个问题：**从税前工资到"到手现金"，每一步到底怎么算的。**
>
> 它不是使用说明（见 [README](../README.md)），也不是城市参数表（见 `SKILL.md` / `AGENTS.md`），
> 而是**计算规则的完整定义**——公式、常量、以及所有"这里其实做过一个选择"的地方。
>
> **与代码的关系**：本文的每个常量、每张税率表都由 `check-sync` 的**检查 I** 与
> `skills/city-salary/assets/calculator.html` 的实际实现逐一比对。
> **改了代码不改这里，CI 会红**——这是本文可信的唯一理由。

---

## 一、计算链总览

| # | 步骤 | 输入 | 输出 | 代码 |
|:-:|------|------|------|------|
| 1 | **输入归一化** | 界面上的原始输入 | 夹取后的工资、各险种基数、公积金比例 | `readInputs()` |
| 2 | **五险一金** | 基数 + 城市费率 | 个人缴费 `siE`+`hfE`、单位缴费 `siC` | `calcContrib()` |
| 3 | **专项附加扣除** | 七项勾选与金额 | 月度可扣 `spT`、年度汇算项 `medicalAnnual` | `calcDeductions()` |
| 4 | **补充扣除** | 税优险/个人养老金/企业年金 | 减税基数 `suppM` = 真实现金支出 `suppCash` | `calcDeductions()` |
| 5 | **个税** | 上述全部 | 当月个税 `curT`、年度预估 `aT`、年终奖 `bi.t` | `calcTax()` |
| 6 | **到手现金** | 税前 − 五险一金 − 个税 − 补充扣除 | `net` | `calcTax()` |

**到手现金的完整定义**（不是"实发工资"）：

```
net = sal − siE − hfE − curT − suppCash
```

其中 `suppCash` = 税优健康险 + 个人养老金 + 企业年金个人缴费。
这三项**既是减税项、也是个人真金白银的支出**，所以既要进扣除、也要从现金里扣出去。

> 生育、工伤两个险种**个人不缴**，只影响单位侧展示，不参与 `net` 的计算。
> 界面把它们列出来是为了完整性，不是算错了。

## 二、输入归一化

| 规则 | 实现 | 说明 |
|------|------|------|
| 区间夹取 | `cl(v,a,b) = max(a, min(b,v))` | 所有基数都夹到该市公布的上下限 |
| 就业起始月 | `effStart(mo, startM) = startM > mo ? mo : startM` | 见下方说明 |
| 公积金比例 | `normHF(v,max)`：`v≤0` → 0；`0<v<5` → 0；否则夹到 `[5,max]` | 见下方说明 |
| 已就业月数 | `mW = max(1, mo − startM + 1)` | 用于累计预扣预缴 |
| 年度就业月数 | `aM = max(1, 12 − startM + 1)` | 用于年度预估；**与当前月份无关** |

### 为什么起始月要夹取

本字段口径是"本年度开始就业时间"。同一年度内不可能出现"现在 3 月、但本年度 12 月才开始就业"，
所以起始月晚于当前月时按当前月计（即已就业 1 个月），并在界面上明示"不能晚于当前月份，已按 N 月计"。

**`calc()` 与 `buildHistory()` 必须共用 `effStart()`**——历史上两页各写各的：单月页用原始值算成
"已就业 1 个月"，历史页却自行改成 3 月入职，同一组输入两页给出不同口径。集中到一个函数后不可能再分叉。

### 为什么公积金比例"填 1% 等于不缴"

公积金缴存比例**没有 1%~4% 这一档**：要么不缴（0），要么在 5%~当地上限之间。
所以 `0<v<5` 一律按 0 处理，而不是"就近取 5%"——后者会凭空给用户加一笔缴存。

上限 `max` 由城市决定：全国绝大多数为 12%，**上海为 7%**（`CITY.hfRateMax`）。
不填时默认 12%。

## 三、五险一金

### 个人侧（决定到手现金）

```
养老   = 养老基数 × 养老个人费率
医疗   = 医疗基数 × 医疗个人费率 + 大额医疗固定额
失业   = 失业基数 × 失业个人费率
长护   = 养老基数 × 长护个人费率      （仅深圳/东莞/珠海/清远，需勾选）
公积金 = 公积金基数 × 比例
siE    = 养老 + 医疗 + 失业 + 长护
```

**五个险种的缴费基数各自独立、可分别调整**——这是刻意的：现实中养老、医疗、失业的基数口径
经常不同（广东按社保年度、医保按自然年；贵州医保基数单独按 80%~300% 核定；新疆医保基数不设上限）。
把基数合成一个输入框会算错。

**大额医疗固定额**是"个人每月固定缴 N 元"这种形态（如北京 3 元、天津 21.67 元、郑州 10.83 元），
不走费率、直接加在个人医疗缴费上。全国有 109 个城市使用这种形态（2026-09-30 由 98 增至 109：补建模江西 11 市大病保险个人额）。

### 单位侧（仅展示，不影响到手现金）

```
siC = 养老基数×养老单位费率 + 医疗基数×医疗单位费率 + 失业基数×失业单位费率
    + 生育基数×生育单位费率 + 工伤基数×工伤单位费率 + 长护基数×长护单位费率
```

深圳按户籍区分养老单位费率：**深户 = 单位费率 + 1%**（地方补充养老保险）。

## 四、专项附加扣除

| 项目 | 月度上限 | 备注 |
|------|---------:|------|
| 子女教育 / 3 岁以下婴幼儿照护 | 10000 | 两个名称共用同一输入框（只换标签），二选一由勾选控制 |
| 继续教育 | 400 | |
| 住房贷款利息 | 1000 | 与住房租金**二选一** |
| 住房租金 | 800 / 1100 / 1500 | 按城市档位取 `CITY.rent`，与房贷利息二选一 |
| 赡养老人 | 3000 | |
| 大病医疗 | 6667 | **只在年度汇算扣除**，见下 |

```
spT = 子女教育 + 继续教育 + 住房（房贷或租金）+ 赡养老人     ← 可用于月度预扣
medicalAnnual = min(大病医疗 × 12, 80000)                    ← 仅年度汇算
```

### 大病医疗为什么特殊

按规定，大病医疗**只能在年度汇算清缴时据实扣除，不进月度预扣预缴**。所以：

- 它**不影响当月个税**，只影响单月页的"年度预估"
- 年度金额按**全年 12 个月**计并封顶 80000，**不随就业月数折算**——税法年度限额与入职月份无关

### 互斥关系怎么实现

- 子女教育 / 婴幼儿照护：`childMode` 只切换标签，共用 `childAmt`
- 房贷利息 / 住房租金：`houseMode` 决定默认值与上限（`0` → 1000，`1` → `CITY.rent`）

## 五、补充扣除

| 项目 | 月度上限 | 说明 |
|------|---------:|------|
| 税优健康险 | 200 | |
| 个人养老金 | 1000 | |
| 企业年金（个人缴费） | 养老基数 × 4% | 上限为**本人缴费工资计税基数**的 4% |

## 六、个税（月度：累计预扣预缴）

```
月扣除 mDed      = siE + hfE + 5000 + spT + suppM
累计收入 cumI    = sal × mW
累计扣除 cumD    = mDed × mW
累计应纳税所得额 cumTx = max(0, cumI − cumD)
累计税额 cumT    = max(0, tx(cumTx).t)
上月累计 pTx     = max(0, sal×(mW−1) − mDed×(mW−1))
当月个税 curT    = max(0, cumT − max(0, tx(pTx).t))
```

**为什么要算"累计"而不是"当月"**：2019 年起工资薪金按**累计预扣法**预缴。
随着累计收入跨过税率级距，**当月税率会逐月上升**，所以同样月薪在不同月份的个税并不相同。
只按单月算会低估高收入者的税负。

### 综合所得预扣率表

| 累计应纳税所得额 ≤ | 税率 | 速算扣除数 |
|------------------:|-----:|-----------:|
| 36000 | 3% | 0 |
| 144000 | 10% | 2520 |
| 300000 | 20% | 16920 |
| 420000 | 25% | 31920 |
| 660000 | 30% | 52920 |
| 960000 | 35% | 85920 |
| 超过 960000 | 45% | 181920 |

税额 = 应纳税所得额 × 税率 − 速算扣除数。

## 七、个税（年度预估：汇算后口径）

```
年度收入 aI    = sal × aM
年度扣除 aDed  = (siE + hfE + 5000 + spT + suppM) × aM + medicalAnnual
年度应纳税所得额 aTx = max(0, aI − aDed)
年度个税 aT    = max(0, tx(aTx).t)
年度税后 aNet  = aI − (siE+hfE)×aM − suppCash×aM − aT
补充扣除年度节税 suppSave = max(0, tx(max(0, aTx + suppM×aM)).t − aT)
```

> ⚠️ **两个"年度个税"口径不同，不要混着比**：
> 单月页"年度预估"是**汇算后口径**（含大病医疗）；历史页"累计个税"是**月度预扣口径**（不含）。
> 两者差额 ≈ 大病医疗的扣除效果——**不相等才是对的**。

## 八、年终奖计税

年终奖支持**单独计税**，并在面板上给出与**并入综合所得**的对比（见下）。

```
月均 m = 奖金 ÷ 12
查月表得税率 r、速算扣除数 d
应缴 = 奖金 × r − d
到手 = 奖金 − 应缴
```

### 年终奖按月换算税率表

| 月均（奖金÷12）≤ | 税率 | 速算扣除数 |
|-----------------:|-----:|-----------:|
| 3000 | 3% | 0 |
| 12000 | 10% | 210 |
| 25000 | 20% | 1410 |
| 35000 | 25% | 2660 |
| 55000 | 30% | 4410 |
| 80000 | 35% | 7160 |
| 超过 80000 | 45% | 15160 |

### 六个临界值陷阱

| 临界点 | 多 1 元少拿 |
|-------:|------------:|
| 36000 | 2309.10 |
| 144000 | 13199.20 |
| 300000 | 13749.25 |
| 420000 | 19249.30 |
| 660000 | 30249.35 |
| 960000 | 87999.45 |

**判定逻辑**：对每个临界点 `lo`，若 `奖金 > lo` 且 `奖金税后 < lo 的税后`，则命中陷阱并警告。
"多 1 元少拿"的金额由 `lo − btx(lo).t` 与 `(lo+1) − btx(lo+1).t` 的差得出。

### 计税方式对比：单独计税 vs 并入综合所得

年终奖有**两种计税方式**，税法允许二选一（一个纳税年度内只允许用一次单独计税）：

```
① 单独计税   = tx(综合所得应纳税所得额).t + btx(奖金).t
② 并入综合所得 = tx(综合所得应纳税所得额 + 奖金).t
差额 = ① − ②    （>0 表示并入更省，<0 表示单独更省，=0 无差别）
```

**这是年度汇算口径**：月度预扣仍按实际选择的方式执行，差额要到次年汇算才体现。
界面在年终奖面板给出两种方式的税额与"建议"，但不代替用户决策。

三种典型结论（都能由上面的公式直接验证）：

| 场景 | 单独计税 | 并入综合所得 | 结论 |
|------|---------:|------------:|------|
| 低所得 + 3.6 万奖金 | 1164.11 | 1360.38 | **单独更省 196.27** |
| 高所得 + 3.6 万奖金 | 49616.10 | 57536.10 | **单独更省 7920.00** |
| 低所得 + 10 万奖金 | 9874.11 | 7760.38 | **并入更省 2113.73** |
| 奖金 36001（陷阱区间） | 3474.21 | 1360.48 | **并入更省 2113.73** |
| 高所得 + 100 万奖金 | 483376.10 | 412901.00 | **并入更省 70475.10** |

> ⚠️ **两个反直觉但正确的结果，不要当成 bug**：
> - **奖金极大时并入反而更省**（高所得 + 100 万那行）。单独计税把整笔奖金推进 45% 档、
>   速算扣除只有 15160；并入后奖金的**边际**税负反而低于单独计税。
> - **陷阱区间内并入更省**。临界值陷阱只存在于单独计税——并入综合所得按年度累进，
>   不存在"多 1 元少拿几千"的断崖。所以**陷阱警告与"建议并入"往往是同一件事的两种表述**。

## 九、历史明细页

逐月独立可调（工资、五险基数、公积金基数、比例），按累计预扣预缴计算：

```
逐月累加：cumIncome += 当月工资;  cumDed += 当月月扣除
当月个税 = max(0, tx(max(0, cumIncome − cumDed)).t − 上月累计税额)
```

**与单月页的两处口径差异**（都是有意的）：

| 项 | 单月页 | 历史页 |
|----|--------|--------|
| 专项附加扣除 | 本页输入 | **取自单月页、各月相同** |
| 大病医疗 | 进年度预估 | **不参与**（月度预扣口径） |

**预测月份**：当前月之后的月份自动生成，标记为预测（界面蓝色、图表虚线），可单独取消勾选。
取消勾选的月份按 0 计缴，不进入累计。

## 十一、口径选择与已知边界

以下是本实现**做过判断**的地方。写出来不是为了免责，是为了让复核者知道该盯哪里。

| # | 选择 | 理由 | 风险 |
|:-:|------|------|------|
| 1 | 企业年金 4% 以**养老缴费基数**为基数 | 政策原文是"本人缴费工资计税基数"，未给出唯一算法；养老基数是最接近的可得值 | 若实际以全部工资为基数，年金扣除会被低估 |
| 2 | 大病医疗**不随就业月数折算** | 税法年度限额与入职月份无关，按 12 个月计并封顶 | 年中入职者可能被高估扣除额（对其有利方向） |
| 3 | 公积金 `0<比例<5` 按**不缴**处理 | 不存在 1%~4% 档位；就近取 5% 会凭空加缴存 | 用户想表达"缴 3%"时会被当作不缴，界面已用"0%(不缴)"提示 |
| 4 | 起始月晚于当前月时**夹取到当前月** | 该字段口径是"本年度开始就业时间" | 若用户真想表达"12 月才入职"，需在 12 月之后再查 |
| 5 | 生育/工伤基数**不参与**到手现金 | 个人不缴这两个险种 | 无 |
| 6 | 深户养老单位费率 **+1%** | 深圳地方补充养老保险 | 仅影响单位侧展示 |
| 7 | 历史页专项附加**取自单月页且各月相同** | 简化；现实中扣除项年中可能变化 | 年中新增扣除项的场景算不准，需自行在单月页调整 |
| 8 | 累计预扣按**自然月连续**计算 | 与实际预缴周期一致 | 年中换工作、断缴的情形未建模 |
| 9 | 公积金**单位比例 = 个人比例**（写死，界面只给一个比例输入框） | 多数城市两者确实相同，且单位侧不影响到手现金 | **上海明确"单位可自主确定"**（各 5%~7%）；若单位缴得比个人多，公积金入账合计会被低估 |
| 10 | 历史页专项附加**各月相同**、不随月份变化 | 简化 | 年中新增/取消扣除项（如孩子满 3 岁、租房换城市）算不准 |

**未建模的缴存项**：上海**补充公积金**（单位与个人各 1%~5%，自愿参加）——`SKILL.md` 已注明"本工具未建模"，此处一并登记。

**不在本实现范围内的**：

- **其他所得形态**：劳务报酬、稿酬、特许权使用费（本工具只算工资薪金所得）
- **并入综合所得的奖金**：季度奖、半年奖、先进奖等（只处理全年一次性奖金）
- **个税减免税项目**：残疾、孤老、烈属的减征，以及自然灾害减免
- **汇算清缴的退补金额**：只给"年度应纳税额"估算，**不给"应退/应补多少"**（见下方"可做未做"）
- **外籍人士八项补贴**、**股权激励**、**离职补偿金**、**多地同时取得工资薪金**

**可做未做（数据齐备、只差呈现）**：汇算退补金额 = 全年累计预扣 − 年度应纳税额（汇算口径）。
两项在 `calcTax()` 里都已算出（`cumT` 与 `aT`），差额即"预计退税为正、补税为负"，
但当前界面没有把它作为一个结论呈现出来。
**注意口径**：本模型下这个差额只可能显示退税（来源是大病医疗扣除，它只在汇算时扣），
所以若要做，必须如实标注为"因大病医疗扣除产生的退税"，不能笼统叫"汇算退补"。

```bash
node tools/check-sync.js      # 检查 I：常量表与税率表 ↔ 实现
node tools/test-calc.js       # 6731 项断言：公式的实际数值验证
```

检查 I 只保证**文档与代码一致**，不保证**代码与税法一致**——后者由 `test-calc.js` 的
独立复算与 `docs/policy-*.md` 的来源文号保证。两者是不同的问题，不要互相替代。
