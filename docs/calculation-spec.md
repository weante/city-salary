# 计算口径白皮书（calculation-spec）

> 这份文档回答一个问题：**从税前工资到"到手现金"，每一步到底怎么算的。**
>
> 它不是使用说明（见 [README](../README.md)），也不是城市参数表（见 `skills/city-salary/references/city-parameters.md` / `AGENTS.md`），
> 而是**计算规则的完整定义**——公式、常量、以及所有"这里其实做过一个选择"的地方。
>
> **与代码的关系**：本文的每个常量、每张税率表都由 `check-sync` 的**检查 I** 与
> `skills/city-salary/assets/calculator.html` 的实际实现逐一比对。
> **改了代码不改这里，CI 会红**——这是本文可信的唯一理由。

## 一、计算链总览

| # | 步骤 | 输入 | 输出 | 代码 |
|:-:|------|------|------|------|
| 1 | **输入归一化** | 界面上的原始输入 | 夹取后的工资、各险种基数、公积金比例 | `readInputs(ctx)` |
| 2 | **五险一金** | 基数 + 城市费率 | 个人缴费 `siE`+`hfE`、单位缴费 `siC` | `calcContrib(I, ctx)` |
| 3 | **专项附加扣除** | 七项勾选与金额 | 月度可扣 `spT`、年度汇算项 `medicalAnnual` | `calcDeductions(I, ctx)` |
| 4 | **补充扣除** | 税优险/个人养老金/企业年金 | 减税基数 `suppM` = 真实现金支出 `suppCash` | `calcDeductions(I, ctx)` |
| 5 | **个税** | 上述全部 | 当月个税 `curT`、年度预估 `aT`、年终奖 `bi.t` | `calcTax(I, C, D)` |
| 6 | **到手现金** | 税前 − 五险一金 − 个税 − 补充扣除 | `net` | `calcTax(I, C, D)` |

上表只列计算链。`renderResult(I, C, D, T, ctx)` 不在计算链内，只负责把结果拼成 HTML 写回页面。

### 函数签名与 ctx（以当前代码为准）

`calc()` 只做编排，并在入口处把顶层 UI 状态一次性收成 `ctx`：

```js
ctx = { city: CITY, med, hk, houseMode, lastHFBase }
```

- `readInputs(ctx)`：读取 `ctx.city` / `ctx.med` / `ctx.lastHFBase`，返回归一化输入，
  并把更新后的 `lastHFBase` 一并返回，由 `calc()` 写回顶层（见 `skills/city-salary/assets/calculator.html#L4523-4554`）。
- `calcContrib(I, ctx)`：只读 `ctx.city` 与 `ctx.hk`；深圳户籍差异使用 `ctx.hk`（`#L4559-4569`）。
- `calcDeductions(I, ctx)`：只读 `ctx.city` 与 `ctx.houseMode`；返回 `spT` / `suppCash`，
  **不再写顶层 `currentSpT` / `currentSupp`**（`#L4573-4601`）。
- `calcTax(I, C, D)`：不读 ctx，只依赖三个对象。
- `renderResult(I, C, D, T, ctx)`：只读 `ctx.city` 与 `ctx.hk`，不再直接读顶层 `CITY` / `hk`
  （`#L4711-4835`）。
- `renderFootNote(city)`：脚注只读传入的 `city`；`selectCity(k)` 是事件入口，仍维护顶层
  `CITY` / `hk` / `houseMode` / `lastHFBase`，但内部渲染通过局部 `city` 显式下发给
  `renderFootNote(city)` / `renderMedBtns(city)`。
- `renderHistTable(city)`：历史表格只读 `city.mat` / `city.hfRateMax`；`toggleAllHist` 从 `histCtx.city` 取城市。
- `buildHistory()`：历史页事件入口，从顶层 `CITY` 取一次当前城市并维护 `histRows` / `histCity`，
  内部使用局部 `city` 与 `calcOut.ctx.med`，不再直接读 `CITY.` / `med`。
- `exportPDF(city)`：只用 `city.name` 拼接 PDF 文件名；文件名格式仍为「城市名 + 工资历史明细.pdf」。

历史页不复用单月页的 `ctx`，而是由 `buildHistory()` 从 `calc()` 的返回值快照一份：

```js
histCtx = { city: CITY, med, spT: calcOut.ded.spT, supp: calcOut.ded.suppCash }
```

`calcHist(histCtx)` 只从这份快照取城市、医保档次和扣除口径（`#L4901`、`#L4954`）；
`currentSpT` / `currentSupp` 两个顶层变量已删除，历史页的事件处理器也显式把 `histCtx` 传进去。

`tools/check-dom.js` 的第 6 项检查会静态校验 `calcContrib` / `calcDeductions` / `calcHist` /
`renderResult` / `renderFootNote` / `renderHistTable` / `exportPDF` 的函数体内不得出现裸
`CITY.` / `hk` / `med` / `houseMode` / `currentSpT` / `currentSupp`，防止后续改动把全局读取加回来。

**到手现金的完整定义**（不是"实发工资"）：

```
net = sal − siE − hfE − curT − suppCash
```

其中 `suppCash` = 税优健康险 + 个人养老金 + 企业年金个人缴费。
这三项**既是减税项、也是个人真金白银的支出**，所以既要进扣除、也要从现金里扣出去。

> 生育、工伤两个险种**个人不缴**，只影响单位侧展示，不参与 `net` 的计算。
> 界面把它们列出来是为了完整性，不是算错了。

## 二、输入归一化

| 规则 | 实现 | 说明 |
|------|------|------|
| 区间夹取 | `cl(v,a,b) = max(a, min(b,v))` | 所有基数都夹到该市公布的上下限 |
| 就业起始月 | `effStart(mo, startM) = startM > mo ? mo : startM` | 见下方说明 |
| 公积金比例 | `normHF(v,max)`：`v≤0` → 0；`0<v<5` → 0；否则夹到 `[5,max]` | 见下方说明 |
| 已就业月数 | `mW = max(1, mo − startM + 1)` | 用于累计预扣预缴 |
| 年度就业月数 | `aM = max(1, 12 − startM + 1)` | 用于年度预估；**与当前月份无关** |

### 为什么起始月要夹取

本字段口径是"本年度开始就业时间"。同一年度内不可能出现"现在 3 月、但本年度 12 月才开始就业"，
所以起始月晚于当前月时按当前月计（即已就业 1 个月），并在界面上明示"不能晚于当前月份，已按 N 月计"。

**`calc()` 与 `buildHistory()` 必须共用 `effStart()`**——历史上两页各写各的：单月页用原始值算成
"已就业 1 个月"，历史页却自行改成 3 月入职，同一组输入两页给出不同口径。集中到一个函数后不可能再分叉。

### 为什么公积金比例"填 1% 等于不缴"

公积金缴存比例**没有 1%~4% 这一档**：要么不缴（0），要么在 5%~当地上限之间。
所以 `0<v<5` 一律按 0 处理，而不是"就近取 5%"——后者会凭空给用户加一笔缴存。

上限 `max` 由城市决定：全国绝大多数为 12%，**上海为 7%**（`CITY.hfRateMax`）。
不填时默认 12%。

## 三、五险一金

### 个人侧（决定到手现金）

```
养老   = 养老基数 × 养老个人费率
医疗   = 医疗基数 × 医疗个人费率 + 大额医疗固定额
失业   = 失业基数 × 失业个人费率
长护   = 养老基数 × 长护个人费率      （仅深圳/东莞/珠海/清远，需勾选）
公积金 = 公积金基数 × 比例
siE    = 养老 + 医疗 + 失业 + 长护
```

**五个险种的缴费基数各自独立、可分别调整**——这是刻意的：现实中养老、医疗、失业的基数口径
经常不同（广东按社保年度、医保按自然年；贵州医保基数单独按 80%~300% 核定；新疆医保基数不设上限）。
把基数合成一个输入框会算错。

**大额医疗固定额**是"个人每月固定缴 N 元"这种形态（如北京 3 元、天津 21.67 元、郑州 10.83 元），
不走费率、直接加在个人医疗缴费上。全国有 110 个城市使用这种形态（2026-09-30 由 98 增至 109：补建模江西 11 市大病保险个人额；2026-10-14 桂林因市政规〔2025〕19号 第四十七条改为「按基数 0.2%」的比例型缴费、固定额字段无法表达而退出，110→109；同日张家口按张政发〔2020〕9号 第十三条「每人每月 15 元、个人负担、单位代缴」补入，109→110）。

### 单位侧（仅展示，不影响到手现金）

```
siC = 养老基数×养老单位费率 + 医疗基数×医疗单位费率 + 失业基数×失业单位费率
    + 生育基数×生育单位费率 + 工伤基数×工伤单位费率 + 长护基数×长护单位费率
```

深圳按户籍区分养老单位费率：**深户 = 单位费率 + 1%**（地方补充养老保险）。

## 四、专项附加扣除

| 项目 | 月度上限 | 备注 |
|------|---------:|------|
| 子女教育 / 3 岁以下婴幼儿照护 | 10000 | 两个名称共用同一输入框（只换标签），二选一由勾选控制 |
| 继续教育 | 400 | |
| 住房贷款利息 | 1000 | 与住房租金**二选一** |
| 住房租金 | 800 / 1100 / 1500 | 按城市档位取 `CITY.rent`，与房贷利息二选一 |
| 赡养老人 | 3000 | |
| 大病医疗 | 年度自付合计（超 15000 部分，限额 80000） | **只在年度汇算扣除**，见下 |

```
spT = 子女教育 + 继续教育 + 住房（房贷或租金）+ 赡养老人     ← 可用于月度预扣
medicalSelf   = 年度医保目录内自付合计（元/年）                ← 用户输入
medicalAnnual = min(max(medicalSelf − 15000, 0), 80000)      ← 仅年度汇算
```

### 大病医疗为什么特殊

按规定，大病医疗**只能在年度汇算清缴时据实扣除，不进月度预扣预缴**。所以：

- 它**不影响当月个税**，只影响单月页的"年度预估"
- 扣除额是**超过 15000 元起付线的部分**，并按 80000 元/年封顶
- **不随就业月数折算**——税法年度限额与入职月份无关；输入本身就是年度金额，不存在"月均×12"换算

### 互斥关系怎么实现

- 子女教育 / 婴幼儿照护：`childMode` 只切换标签，共用 `childAmt`
- 房贷利息 / 住房租金：`houseMode` 决定默认值与上限（`0` → 1000，`1` → `CITY.rent`）

## 六、个税（月度：累计预扣预缴）

```
月扣除 mDed      = siE + hfE + 5000 + spT + suppM
累计收入 cumI    = sal × mW
累计扣除 cumD    = mDed × mW
累计应纳税所得额 cumTx = max(0, cumI − cumD)
累计税额 cumT    = max(0, tx(cumTx).t)
上月累计 pTx     = max(0, sal×(mW−1) − mDed×(mW−1))
当月个税 curT    = max(0, cumT − max(0, tx(pTx).t))
```

**为什么要算"累计"而不是"当月"**：2019 年起工资薪金按**累计预扣法**预缴。
随着累计收入跨过税率级距，**当月税率会逐月上升**，所以同样月薪在不同月份的个税并不相同。
只按单月算会低估高收入者的税负。

### 综合所得预扣率表

| 累计应纳税所得额 ≤ | 税率 | 速算扣除数 |
|------------------:|-----:|-----------:|
| 36000 | 3% | 0 |
| 144000 | 10% | 2520 |
| 300000 | 20% | 16920 |
| 420000 | 25% | 31920 |
| 660000 | 30% | 52920 |
| 960000 | 35% | 85920 |
| 超过 960000 | 45% | 181920 |

税额 = 应纳税所得额 × 税率 − 速算扣除数。

## 七、个税（年度预估：汇算后口径）

```
年度收入 aI    = sal × aM
年度扣除 aDed  = (siE + hfE + 5000 + spT + suppM) × aM + medicalAnnual
年度应纳税所得额 aTx = max(0, aI − aDed)              ← 仅工资综合所得
年度个税 aT    = max(0, tx(aTx).t)
其他所得收入额 otherIncome = 劳务×80% + 稿酬×56% + 特许×80%
aTxAll = aTx + otherIncome                            ← 并入其他所得后
aTAll  = max(0, tx(aTxAll).t)                         ← 界面"年度个人所得税（全口径）"
年度税后 aNet  = aI + otherIncome − (siE+hfE)×aM − suppCash×aM − taxFinal
补充扣除年度节税 suppSave = max(0, tx(max(0, aTxAll + suppM×aM)).t − aTAll)
```

> **单月页只显示一个"年度个人所得税"口径**：`aTAll`（工资 + 其他所得并入后的年度税额，减免前）。
> 减免税另列一行 `reliefAmt`，减免后税额 `taxFinal = aTAll − reliefAmt`。
> 「年度汇算退补」= `prepaidTotal − taxFinal`，在界面上分解为
> **工资部分 + 其他所得部分 + 减免**，三项相加恒等于退补额（不再出现多个互不相等的"年度个税"）。

```
prepaidTotal = prepaid12 + otherPre          ← 工资全年预扣 + 其他所得支付方预扣
taxFinal     = max(0, aTAll − reliefAmt)     ← 全口径年度应纳（无减免时即 aT）
settleTotal  = prepaidTotal − taxFinal       ← >0 可退，<0 补
settleSalary = prepaid12 − aT
settleOther  = otherPre − otherSettle
settleRelief = reliefAmt
settleTotal  = settleSalary + settleOther + settleRelief
```

> ⚠️ **两个"年度个税"仍未混用**：单月页"年度预估"是**汇算后口径**（含大病医疗、其他所得与减免）；
> 历史页"累计个税"是**月度预扣口径**（不含）。两者差额 ≈ 汇算退补，**不相等才是对的**。

## 八、年终奖计税

年终奖支持**单独计税**，并在面板上给出与**并入综合所得**的对比（见下）。

```
月均 m = 奖金 ÷ 12
查月表得税率 r、速算扣除数 d
应缴 = 奖金 × r − d
到手 = 奖金 − 应缴
```

### 年终奖按月换算税率表

| 月均（奖金÷12）≤ | 税率 | 速算扣除数 |
|-----------------:|-----:|-----------:|
| 3000 | 3% | 0 |
| 12000 | 10% | 210 |
| 25000 | 20% | 1410 |
| 35000 | 25% | 2660 |
| 55000 | 30% | 4410 |
| 80000 | 35% | 7160 |
| 超过 80000 | 45% | 15160 |

### 六个临界值陷阱

| 临界点 | 多 1 元少拿 |
|-------:|------------:|
| 36000 | 2309.10 |
| 144000 | 13199.20 |
| 300000 | 13749.25 |
| 420000 | 19249.30 |
| 660000 | 30249.35 |
| 960000 | 87999.45 |

**判定逻辑**：对每个临界点 `lo`，若 `奖金 > lo` 且 `奖金税后 < lo 的税后`，则命中陷阱并警告。
"多 1 元少拿"的金额由 `lo − btx(lo).t` 与 `(lo+1) − btx(lo+1).t` 的差得出。

### 计税方式对比：单独计税 vs 并入综合所得

年终奖有**两种计税方式**，税法允许二选一（一个纳税年度内只允许用一次单独计税）：

```
① 单独计税   = tx(综合所得应纳税所得额).t + btx(奖金).t
② 并入综合所得 = tx(综合所得应纳税所得额 + 奖金).t
差额 = ① − ②    （>0 表示并入更省，<0 表示单独更省，=0 无差别）
```

**这是年度汇算口径**：月度预扣仍按实际选择的方式执行，差额要到次年汇算才体现。
界面在年终奖面板给出两种方式的税额与"建议"，但不代替用户决策。

三种典型结论（都能由上面的公式直接验证）：

| 场景 | 单独计税 | 并入综合所得 | 结论 |
|------|---------:|------------:|------|
| 低所得 + 3.6 万奖金 | 1164.11 | 1360.38 | **单独更省 196.27** |
| 高所得 + 3.6 万奖金 | 49616.10 | 57536.10 | **单独更省 7920.00** |
| 低所得 + 10 万奖金 | 9874.11 | 7760.38 | **并入更省 2113.73** |
| 奖金 36001（陷阱区间） | 3474.21 | 1360.48 | **并入更省 2113.73** |
| 高所得 + 100 万奖金 | 483376.10 | 412901.00 | **并入更省 70475.10** |

> ⚠️ **两个反直觉但正确的结果，不要当成 bug**：
> - **奖金极大时并入反而更省**（高所得 + 100 万那行）。单独计税把整笔奖金推进 45% 档、
>   速算扣除只有 15160；并入后奖金的**边际**税负反而低于单独计税。
> - **陷阱区间内并入更省**。临界值陷阱只存在于单独计税——并入综合所得按年度累进，
>   不存在"多 1 元少拿几千"的断崖。所以**陷阱警告与"建议并入"往往是同一件事的两种表述**。

## 九、历史明细页

逐月独立可调（工资、五险基数、公积金基数、比例），按累计预扣预缴计算：

```
逐月累加：cumIncome += 当月工资;  cumDed += 当月月扣除
当月个税 = max(0, tx(max(0, cumIncome − cumDed)).t − 上月累计税额)
```

**与单月页的两处口径差异**（都是有意的）：

| 项 | 单月页 | 历史页 |
|----|--------|--------|
| 专项附加扣除 | 本页输入 | **取自单月页、各月相同** |
| 大病医疗 | 进年度预估 | **不参与**（月度预扣口径） |

实现上，`buildHistory()` 先调 `calc()`，再把 `{city, med, spT: calcOut.ded.spT, supp: calcOut.ded.suppCash}`
快照进 `histCtx`，然后调 `calcHist(histCtx)`；历史页的编辑/勾选事件同样传 `histCtx`。
这样可以保证“各月相同”的扣除口径来自同一次单月计算结果，而不是从顶层 `currentSpT` / `currentSupp` 隐式读取。

**预测月份**：当前月之后的月份自动生成，标记为预测（界面蓝色、图表虚线），可单独取消勾选。
取消勾选的月份按 0 计缴，不进入累计。

## 十一、口径选择与已知边界

以下是本实现**做过判断**的地方。写出来不是为了免责，是为了让复核者知道该盯哪里。

| # | 选择 | 理由 | 风险 |
|:-:|------|------|------|
| 1 | 企业年金 4% 以**养老缴费基数**为基数 | 政策原文是"本人缴费工资计税基数"，未给出唯一算法；养老基数是最接近的可得值 | 若实际以全部工资为基数，年金扣除会被低估 |
| 2 | 大病医疗按**年度自付合计**据实扣除（超 15000 部分，限额 80000），不随就业月数折算 | 税法按纳税年度计算，年度限额与入职月份无关 | 用户若误填月度自付额，扣除会被低估；界面已标注"元/年" |
| 3 | 公积金 `0<比例<5` 按**不缴**处理 | 不存在 1%~4% 档位；就近取 5% 会凭空加缴存 | 用户想表达"缴 3%"时会被当作不缴，界面已用"0%(不缴)"提示 |
| 4 | 起始月晚于当前月时**夹取到当前月** | 该字段口径是"本年度开始就业时间" | 若用户真想表达"12 月才入职"，需在 12 月之后再查 |
| 5 | 生育/工伤基数**不参与**到手现金 | 个人不缴这两个险种 | 无 |
| 6 | 深户养老单位费率 **+1%** | 深圳地方补充养老保险 | 仅影响单位侧展示 |
| 7 | 历史页专项附加**取自单月页且各月相同** | 简化；现实中扣除项年中可能变化 | 年中新增扣除项的场景算不准，需自行在单月页调整 |
| 8 | 累计预扣按**自然月连续**计算 | 与实际预缴周期一致 | 年中换工作、断缴的情形未建模 |
| 9 | 公积金**个人与单位比例可独立设置**（`hfRate` / `hfRateComp`，各自受该市上限约束） | 上海等单位可自主确定单位比例；单位侧不影响到手现金 | 若只填一个比例，公积金入账合计会被低估或高估；界面已拆成两个输入框 |
| 10 | 历史页专项附加**各月相同**、不随月份变化 | 简化 | 年中新增/取消扣除项（如孩子满 3 岁、租房换城市）算不准 |

**未建模的缴存项**：上海**补充公积金**（单位与个人各 1%~5%，自愿参加）——`SKILL.md` 已注明"本工具未建模"，此处一并登记。

**不在本实现范围内的**：

- **其他所得的逐笔建模**：本工具按年度合计一次性减除 20%（每笔 >4000 时与逐笔等价），不建模"每次 ≤4000 减 800"的多次拆分
- **并入综合所得的奖金**：季度奖、半年奖、先进奖等（只处理全年一次性奖金）
- **汇算的其他调整项**：公益捐赠扣除、境外所得抵免、多预缴/少预缴的税额差异
- **外籍人士八项补贴**、**股权激励**、**离职补偿金**、**多地同时取得工资薪金**

**已实现**：全口径汇算退补 = 全年预扣（工资 `prepaid12` + 其他所得 `otherPre`）− 汇算应纳 `taxFinal`
（`aTAll − 减免`），界面同时给出"工资部分 + 其他所得部分 + 减免"的分解，三项相加恒等于退补额。

> **口径提醒**：工资预扣满 12 个月、无其他所得、无减免时退补为 0；只有存在大病医疗、其他所得或减免时才非零。
> 因此界面上的"可退/需补"必须与服务端的全口径税额一起读，不能只看差额就断言"一定退税"。
