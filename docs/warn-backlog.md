## 一、这份清单解决什么问题

计算器里带 `warn:true` 的城市会在页面显示橙框「数据待确认」。但"待确认"本身不是可执行的——
**待确认什么、什么时候确认、确认到哪一步算完**，原先只散落在各城 `note` 里。这份清单把它结构化：
按**缺哪个参数**分层，每层给出补齐动作与下一次核查时间。

当前状态：全国 337 城中 **172 城**带 warn（占 51.0%），
分布见下表。**缺口不代表数据错误**——项目原则是"查不到就标注、绝不编造"，
这些城市用的都是已公开的最近一期数值或明确的省级区间，只是尚未取到本年度官方文件。

## 五、维护方式

1. 取到官方文件后：更新 `calculator.html` 的 `CITIES` 条目（数值 + `note`），**去掉 `warn:true`**；
2. 同步 `AGENTS.md` / `SKILL.md` / `README.md` 的对应参数行；
3. 跑 `node tools/gen-warn-backlog.js --update` 重新生成本清单；
4. 跑 `npm test` 全套确认。

> 反过来：**新增 warn 城市时也必须重新生成**，否则检查 H 会因集合不一致而失败。
> 这条约束是有意的——缺口只有被登记才算被追踪。
