# 省份年度基线表（city-salary）

> 本文档是 `tools/province-year.js` 的可读版本，两者必须一致。
> **机器可读的权威副本是 `tools/province-year.js`** —— `check-sync.js` 检查 E 与 `test-calc.js` 第 12 节都直接 `require` 它。改年度请先改该文件，再改 `calculator.html` 的 `opt` 覆盖，最后跑 `node tools/check-sync.js`。

## 一、这张表解决什么问题

页脚会向用户展示一行「数据依据：<城市> <年度>年度」。这个年度必须与**该城市参数实际所属的年度**一致——否则用户会以为基数已经更新，从而做出错误的薪资判断。

**真实事故（2026-09-27 修复）**：`CIU()` 工厂的默认值是 `dataYear:"2026"`，新增省份城市时开发者只覆盖了 `region`、忘了覆盖 `dataYear`，导致 **100 个城市**的页脚显示「2026年度」，而它们的参数实际是 2025 年度基数、2026 年度尚未公布：

| 受影响省份 | 城市数 | 修复前页脚 | 修复后页脚 |
|-----------|:------:|-----------|-----------|
| 吉林 | 9 | `2026年度` | `2025-2026年度` |
| 黑龙江 / 江苏 / 浙江 / 河南 / 湖北 / 江西 / 海南 | 82 | `2026年度` | `2025年度（2026年度待公布）` |
| 福建 | 9 | `2026年度` | `2025-2026年度` |
| **合计** | **100** | | |

> 注：代码审查报告（2026-09-27）识别出 87 城（未含湖北）。复核时发现**湖北 13 市州同属此问题**——它用的是 `鄂人社发〔2025〕28号` 的 2025 年度基数，`鄂医保函〔2024〕91号` 明确 2026-07-01 起沿用至新标准出台，而页脚同样显示「2026年度」。

原来的 B 检查只断言「城市的 4 个基数数值出现在文档里」，**不检查 `dataYear` 与文档口径的一致性**，所以这类漂移拦不住。现在由**检查 E** 负责。

## 二、为什么有两种跨年度写法

`dataYear` 取 `'2025'` / `'2025-2026'` / `'2026'` 三值。`'2025-2026'` 用于两种不同情形，含义都是「该城市当前生效的参数横跨两个年度」：

| 情形 | 例子 | 说明 |
|------|------|------|
| **① 社保年度跨年** | 广东、吉林 | 基数是 2025.7–2026.6 社保年度，且 2026 年 7 月的调整未落地 / 未发生 |
| **② 同一城市内险种分属不同年度** | 福建 | 养老·失业基数属 2025 年度，医保·工伤基数属 2026 年度 |

因此 `'2025-2026'` 的城市**不再叠加**「待公布」提示（`dataNext` 为 `null`）——年度已经跨到 2026，再提示「2026 年度待公布」会自相矛盾。这类城市的待核实状态由 `warn` 标记与 `note` 说明承载。

## 四、三条断言契约

| 位置 | 断言 |
|------|------|
| `tools/check-sync.js` 检查 E | 每个城市的 `CITIES[x].dataYear` 与 `dataNext` 必须与基线表**完全相等**；反向还要求基线表登记的每个省份分组都至少有一个城市在用（防新增省份只改一边） |
| `tools/test-calc.js` 第 12 节 | 12.1 `dataYear` 取值只能在三值集合内；12.2 逐城与基线表比对；12.3 受影响 9 省抽查 + 未受影响省份（京/深/穗）不得被误改；12.4 **页脚实际渲染文案**断言（含「（2026年度待公布）」提示）；12.5 反向校验提示标记 |
| `tools/check-sync.js` 检查 C | 拦截年度分组措辞回退（吉林被列回 2026 年度组、遗漏湖北等） |

## 五、维护流程

年度基数更新时按顺序执行：

1. 改 `tools/province-year.js`（权威副本）+ 本文档第三节表格；
2. 改 `skills/city-salary/assets/calculator.html` 中对应城市的 `opt` 覆盖（`dataYear` / `dataNext`）；
3. 若涉及基数数值本身，同步改 `AGENTS.md` 与 `SKILL.md` 的参数行；
4. `node tools/sync.js` → `node tools/test-calc.js` → `node tools/check-golden.js` → `node tools/check-dom.js` → `node tools/check-sync.js` → `node tools/test-export.js` 六连验证；
5. 新增省份时，**必须同时在基线表登记**，否则检查 E 会报「省份分组未登记」。

## 六、写作注意

检查 C 的陈旧表述模式会拦截几个**旧的年度分组字符串**。编写或修改文档时不要原样引用它们（哪怕是作为「反面例子」），否则会被自己的守卫拦下——描述问题请用「吉林曾被列进 2026 年度组」这类措辞，而不是粘贴原文。
