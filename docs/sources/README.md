### 一条经验

贵阳这条最能说明问题：Agent 说「文号可能记错」是**推测**；
复核原文后才知道是「**数值对、文号无从证实**」——两者的处置完全不同。
**若直接采信 Agent 的推测去改文号，就会改错。**
## 来源判定标准（2026-10-01 用户确认）

| 类别 | 是否算官方 | 例子 |
|------|:----------:|------|
| 各级政府门户 / 人社局 / 医保局 / 税务局 | ✅ | `*.gov.cn` |
| **公积金中心等事业单位官网** | ✅ | `cxzfgjj.com`、`nxzfgjj.com`、`msgjj.com`、`zfgjj.cn` |
| 政府文件托管在事业单位域名下 | ✅ | 同上，标注 `officialDomain: false` 即可 |
| 商业聚合站 / 媒体 / 博客 | ❌ | `66zhonglv`、`szhclawfirm`、`zhiliaoshebao`、`shebao.southmoney`、本地宝、知乎、新浪、腾讯 |
| 征求意见稿 / 阶段性降费（未到期除外） | ❌ | 见下表「不可用来源」 |

记录时用 `officialDomain` 字段区分：`true` = `.gov.cn`，`false` = 事业单位官网（`.com/.cn`）。
## 一次崩溃验证了「边查边写」的价值

2026-10-01 会话中途 **DSH 崩溃**。但因为第二轮已改为
「**边查边写、每 2~3 城写一次文件**」，崩溃时 **9 个分组的 JSON 全部已落盘**，**零丢失**。
相比之下第一轮「查完再一次性返回」的做法，因返回值截断丢了 21/28 个省。

**结论：长任务必须把中间结果持久化到文件，不要攒在内存或返回值里。**
## 技术要点（复用）

1. **知识库是 SPA**，`--dump-dom` 需 `--virtual-time-budget=22000` 起，20 秒内常拿不全，可重试。
2. **PDF 用 `python` + `pypdf`**（已装）；**DOCX 用 python `zipfile` 读 `word/document.xml`**。
   Jina 抓 PDF 常失败（如河南那份只回 799 字符，下载后用 pypdf 拿到 2558 字符正文）。
3. **知识库条目的「答复依据」是折叠面板**，内容不在初始 DOM 里，`--dump-dom` 拿不到。
4. **大规模 fan-out 的结果要写文件**，不要靠返回值传回 —— 返回值有长度上限，
   上一轮 9 个 Agent 的结果只回来了 7/28 个省。
5. **子 Agent 会在仓库根目录留临时文件** —— 抓取产物请写系统临时目录。
